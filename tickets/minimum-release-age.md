# Feature: 릴리스 시각 기준 업데이트 유예

## 상태

2026-09-16 로컬 구현과 검증을 완료했습니다. 기능을 포함한 애플리케이션은 아직 클러스터에 배포하지 않았습니다.

- `./gradlew test build`: 테스트 202개 통과, 실패·오류·건너뜀 0개, 빌드 성공.
- UI 스크립트의 `node --check` 통과.
- 기간 파싱, 시각과 digest 매칭, 최신 후보 교체, cron·check-now, 조회 실패 후 재시도, API 설정값 노출을 검증했습니다.

사용 중인 이미지와 API에 대한 [조사 결과](minimum-release-age-investigation.md)를 바탕으로 Docker Hub의 마지막 push 시각을 사용하기로 확정했습니다. 시각 조회 실패 시에는 적용을 보류하고 다음 확인에서 재시도합니다.

환경 준비로 Kavita·Reloader·Immich server·Immich machine learning을 공식 Docker Hub 이미지로 전환했으며, 현재 관리 대상은 Docker Hub 19개와 개인 레지스트리 2개입니다. 이미지 경로 전환 당시에는 사용자 요청에 따라 digest 없이 태그만 적용했습니다. 이 환경 준비 작업과 이번 유예 기능의 배포는 별개입니다.

## 배경

Self-hosted 서비스의 신규 릴리스에 버그가 포함되어 출시 직후 핫픽스가 연이어 나오는 경우가 있습니다. 일정 시간이 지난 이미지만 적용하여 초기 문제에 대응할 시간을 확보하려는 기능입니다. 시간 경과 자체가 이미지의 안전성을 검증하는 것은 아닙니다.

## 확정된 요구사항과 구현

### 설정

Deployment annotation `watch-cluster.io/minimum-release-age`를 사용합니다.

```yaml
annotations:
  watch-cluster.io/enabled: "true"
  watch-cluster.io/strategy: "version"
  watch-cluster.io/minimum-release-age: "3d"
```

- 양의 정수와 `h`, `d`, `w`를 조합합니다. 예시: `12h`, `3d`, `3w`.
- `1d = 24h`, `1w = 7d`로 계산합니다.
- 미설정 또는 `0`이면 기존 즉시 적용 동작을 유지합니다.
- 소수, 음수, 복합 단위, 공백, 지원하지 않는 단위, 숫자 오버플로 등 잘못된 값은 경고를 기록하고 유예 설정을 무시합니다.
- UI는 설정값을 표시하며, 설정 변경은 Deployment annotation으로 수행합니다.

### 시각 기준과 조회 실패

```text
현재 시각 >= 선택한 이미지의 마지막 push 시각 + 설정한 유예 기간
```

- watch-cluster의 최초 발견 시각, OCI 이미지 생성 시각, 프로젝트 릴리스 게시 시각으로 대체하지 않습니다.
- Docker Hub 태그 API 응답에서 선택한 digest와 연결된 시각만 사용합니다.
- 최상위 태그/인덱스 digest가 일치하면 `tag_last_pushed`를 사용합니다.
- 플랫폼 이미지 digest가 일치하면 해당 `images[].last_pushed`를 사용합니다.
- 이 시각은 마지막 push 시각이며 최초 공개 시각을 보장하지 않습니다. 같은 이미지의 재게시로 대기가 추가될 수 있습니다.
- 시각 누락·잘못된 시각·digest 불일치·조회 실패는 적용을 보류합니다. 다음 cron 또는 수동 확인에서 다시 조회합니다.
- 유예 설정이 유효하고 양수인 미지원 레지스트리도 보류합니다. GHCR 시각 API는 이번 구현에 포함하지 않습니다.

### 최신 후보 선택

기존 업데이트 전략상 최신 후보 하나만 대상으로 유예를 판단합니다. 최신 후보가 유예 중이어도 이전 후보를 대신 적용하지 않습니다.

예를 들어 현재 버전이 `1.1.0`, 유예 기간이 3일이고 `1.2.0` 이미지는 9월 1일 00:00, `1.2.1` 이미지는 9월 3일 00:00에 push되었다면 다음과 같이 동작합니다.

- 9월 4일 확인에서는 `1.2.0`을 건너뛰고 현재 버전을 유지합니다.
- 9월 6일 00:00 이후 cron 확인에서 `1.2.1`이 여전히 최신 후보이고 다른 조건도 충족하면 적용합니다.
- 그 사이 새 후보가 나오면 새 후보의 push 시각을 기준으로 평가합니다.

후속 버전 발견 시점부터 타이머를 시작하지 않습니다. 이미 충분히 오래된 이미지를 처음 발견해도 추가 대기하지 않습니다. 출시가 잦으면 업데이트가 계속 미뤄질 수 있습니다.

### latest와 적용 대상 보장

- `latest`, `alpine`, `release-openvino` 등 변경 가능한 태그는 기존 latest 전략의 digest 비교를 사용합니다.
- 같은 태그의 다른 digest는 별개의 후보로 평가합니다.
- 유예를 통과한 경우 태그와 검증한 digest를 함께 지정하여 적용합니다. 확인 후 태그가 바뀌더라도 유예를 검증하지 않은 이미지가 pull되지 않도록 하기 위한 동작입니다.
- 미설정·`0`·제외 레지스트리는 기존 적용 동작을 유지합니다.

### 개인 레지스트리 제외

사용자가 직접 개발하고 사용하는 `hub.sixtyfive.me` 이미지는 유예 기간을 항상 `0`으로 취급합니다. 공개 시각을 조회하지 않고 기존 업데이트 조건을 따릅니다.

이 예외를 코드에 고정하지 않고 `MINIMUM_RELEASE_AGE_EXCLUDED_REGISTRIES` 환경 변수로 지정합니다. 쉼표로 구분한 정확한 레지스트리 호스트가 대상이며, 애플리케이션 자체의 기본 제외 목록은 비어 있습니다.

제공된 `k8s/configmap.yaml`에는 `hub.sixtyfive.me`를 지정했고 `k8s/deployment.yaml`에서 환경 변수로 연결했습니다. 기능 배포 시 두 설정을 함께 반영해야 합니다. 모든 사설 레지스트리를 자동 제외하지 않습니다.

### 실행 시점과 상태 표시

- 유예 종료 후 다음 cron 실행에서 최신 후보와 시각을 재검증합니다. 별도 타이머는 만들지 않습니다.
- `check-now`도 동일한 유예 조건을 따릅니다. 강제 무시 기능은 제공하지 않습니다.
- `RELEASE_AGE_WAITING`: UI에 `유예 대기`를 표시하고 이력에 후보 digest, push 시각, 적용 가능 시각을 기록합니다.
- `RELEASE_TIME_UNKNOWN`: UI에 `공개 시각 확인 불가`를 표시하고 이력에 후보와 보류 사유를 기록합니다.
- 수동 확인 결과는 Kubernetes 이벤트에도 기록합니다.
- 후보와 타이머를 annotation에 영속화하지 않습니다. 재시작 후 시각을 다시 조회하므로 발견 시점부터 대기가 다시 시작되지 않습니다. 확인 이력은 기존과 같이 메모리에만 유지합니다.

## 구현 위치

- `MinimumReleaseAge`: 설정 파싱과 오버플로 처리.
- `DockerRegistryClient.getImagePushedAt`: digest와 연결된 Docker Hub push 시각 조회.
- `ReleaseAgePolicy`: 제외 레지스트리, 유예 충족, 시각 확인 실패 판단.
- `ImageChecker.checkReleaseAge`: 기존 이미지 조회 인증과 정책 연결.
- `DeploymentWorker`: 적용 직전 유예 판단, cron·수동 확인 결과 기록.
- Admin API와 UI: 설정값 및 유예·시각 확인 실패 상태 표시.

## 후속 개선: 멀티 아키텍처

서브 에이전트 리뷰에서 latest 전략의 플랫폼별 digest를 Deployment 전체에 고정하는 제약을 확인했습니다. 현재 운영 환경은 x86_64 단일 아키텍처이므로 사용자와 이번 구현 범위에서 제외하기로 합의했습니다. 혼합 아키텍처를 도입하기 전에는 비교용 플랫폼 digest와 배포용 index digest를 분리하고, 적용할 index의 유예 조건 및 플랫폼별 rollout을 검증해야 합니다.
